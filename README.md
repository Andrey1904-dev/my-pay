# CASE.PLACE SALARY

Текущая версия: **V1.01** (техническая версия пакета и iOS: `1.0.1`).

**CASE.PLACE SALARY** — личный кабинет для сотрудников CASE.PLACE: учёт смен по графику 2/2, упаковки чехлов и заработка в одном интерфейсе.

Приложение фиксирует количество упакованных чехлов, показывает доход за смену и месяц, ведёт календарь рабочих дней, статистику, финансы и цели. Работает офлайн (данные на устройстве), а при входе в аккаунт синхронизируется через Supabase. Чехлы можно вносить прямо из Telegram.

Лендинг: <https://andrey1904-dev.github.io/my-pay/> · веб-приложение: <https://andrey1904-dev.github.io/my-pay/app.html> · iPhone: проект Xcode в папке [`ios/`](ios/README_IOS.md) · публикация: [`APP_STORE.md`](APP_STORE.md)

## Новый лендинг из MyPayDesign

Главная страница (`/`) собрана по дизайну из [`MyPayDesign`](https://github.com/Andrey1904-dev/MyPayDesign): тёмная графитовая палитра с фирменным оранжевым, анимированный hero с макетом телефона, прокручиваемые экраны, интерактивный калькулятор смены, демо Telegram-бота и блоки о финансовых функциях. Кнопки «Открыть приложение» ведут в сохранённый личный кабинет на `/app.html`.

Сам кабинет остаётся отдельным функциональным PWA: вход, локальные данные, синхронизация, календарь, статистика, финансы, Telegram и офлайн-режим продолжают работать на странице `/app.html`.

## Возможности

- главный экран «Моя смена»: ввод чехлов, праздничная ставка, итог смены, прогресс по цели месяца;
- календарь 2/2 с внесёнными сменами, выбор дня и окно смены (чехлы, часы, премия, комментарий, шаблоны);
- статистика месяца: заработок, чехлы, средняя смена, лучшая смена, серия, график по сменам, список смен;
- финансы (v17, по мотивам Копилки): счета и балансы, доходы/расходы/переводы, категории с лимитами, регулярные платежи с напоминаниями, долги «я должен / мне должны», копилки с историей пополнений, аванс/зарплата, советник по бюджету;
- вход через Apple, Google или email; удаление аккаунта из приложения;
- нативное iOS-приложение (SwiftUI, iOS 16+) с полным паритетом функций и общими данными;
- резервная копия и восстановление (JSON), экспорт в CSV;
- светлая, тёмная и системная темы;
- PWA: установка на экран телефона, офлайн-оболочка через Service Worker;
- аккаунт и синхронизация через Supabase (Auth + Postgres + RLS), офлайн-очередь изменений;
- Telegram-бот: карточки с inline-кнопками, чехлы за любой день, расходы одной строкой («350 обед») с лимитами, календарь, прогноз, напоминания и итоги месяца.

## Дизайн

- Лендинг (`src/index.css`) — фирменный ночной стиль из MyPayDesign: почти чёрный фон, тонкая координатная сетка, зерно, графитовые панели, оранжевые акценты и выразительная типографика. Hero, карточки и секции адаптируются к мобильному экрану; движения отключаются через `prefers-reduced-motion`.
- Кабинет (`style.css`) сохраняет дизайн-систему «Ledger»: графит `#14161a` / `#23262d`, фирменный оранжевый `#ff5a1f` (в тёмной теме `#ff6a33`), тёплые нейтрали `#eeeeea` / `#f5f5f2` / `#ffffff`. Зеркало токенов для iPhone — `ios/CasePlaceSalary/Theme.swift`.
- Шрифт Manrope подключён через `@font-face` с `unicode-range` (4 сабсета) и `font-display: swap`; системный стек — запасной.
- Все пары «текст / фон» проверены на контраст ≥ 4.5:1 (WCAG AA) в обеих темах; на оранжевых заливках используется тёмный текст, на графите — белый и `#b9bec8`.
- Минимальный размер текста — 10.5 px (только капс-метки), основной — 15 px, единая сетка отступов, радиусов (`--r-sm/md/lg/xl`) и теней.
- Тёмная тема — отдельный набор токенов (`body.dark`), а не инверсия; инверсные элементы (внесённые дни, тёмные кнопки, тосты) автоматически меняют полярность.
- Свои диалоги подтверждения и ввода суммы вместо системных `confirm()` / `prompt()`; уважается `prefers-reduced-motion`, есть стили печати.

## Модель оплаты

- Обычная смена: 1 900 ₽ выход + 200 ₽ доплата за обед = 2 100 ₽, с районным коэффициентом Екатеринбурга 1,15 (15%) = **2 415 ₽**.
- Сдельная часть: 7 ₽ за чехол × 25% = **1,75 ₽ за чехол**. Районный коэффициент на сделку не начисляется; в праздник сделка не удваивается.
- Пример: 1000 чехлов → (1 900 + 200) × 1,15 + 1 750 = **4 165 ₽**.
- Праздничная смена: (1 900 × 2 + 200) × 1,15 = **4 600 ₽** фиксированная часть; с 1000 чехлов — **6 350 ₽**.
- **23-го:** только выходы за 1–15 число текущего месяца (1 900 ₽ обычный, 3 800 ₽ праздничный).
- **8-го:** выходы за 16-е–последний день прошлого месяца + обеды и районный коэффициент за весь прошлый месяц + вся сделка и премии за прошлый месяц. Это полный заработок прошлого месяца минус его аванс.
- Ожидаемая выплата — по внесённым сменам, не прогноз будущих смен и не подтверждение перевода денег.
- `итог = ставка + чехлы × цена × процент / 100 (+ премия)`.

Все параметры меняются в «Ещё → Настройки расчёта» и синхронизируются с таблицей `settings`.

## Telegram-бот

Бот — второй интерфейс к тем же данным: чехлы, смены и расходы, внесённые из чата, сразу видны на сайте и в iPhone-приложении. Каждый ответ — карточка с inline-кнопками, которые редактируют то же сообщение, а не засоряют чат.

**Чехлы**
- `350`, `350 + 500`, `чехлы 350`, `упаковал 1200 чехлов` — задать значение за сегодня (если смена уже внесена, бот спросит: добавить или заменить);
- `+500` — добавить к текущему; кнопки `+100 / +500 / +1000` есть и в постоянной клавиатуре, и под карточкой смены;
- `вчера 900`, `позавчера +100`, `27.09 900` — смена за другой день;
- карточка смены: чехлы, мотивация, заработок (ставка + сделка), время до конца смены и **темп** — сколько получится к 19:00, если продолжать так же.

**Деньги (как в Копилке)**
- `350 обед`, `-1200 продукты карта`, `потратил 700 на кино` — расход: бот сам подбирает категорию по словарю (еда, транспорт, жильё, здоровье, развлечения, связь, семья, покупки) или по имени категории пользователя, выбирает счёт (по имени в конце строки, иначе наличные) и показывает остаток лимита категории и «свободно в этом месяце»;
- `доход 5000 премия`, `+15000 аванс` — доход;
- `/spent` («💸 Расходы») — расходы месяца по категориям с прогресс-барами лимитов и последними операциями; кнопка «↩️ Отменить» под записью удаляет её.

**Отчёты и навигация**
- `/today` — карточка дня, `/month` — итоги месяца с прогресс-баром цели, `/forecast` — прогноз и «сколько нужно за смену», `/calendar` — моноширинный календарь месяца (▪ внесена, · по графику, ▸ сегодня) с листанием по месяцам, `/last` — последняя смена;
- `/settings` («⚙️ Ещё») — ставки и график, включение напоминаний и время вечернего напоминания (19–22) кнопками;
- `/undo`, `/holiday`, `/notify_on`, `/notify_off`, `/menu` (вернуть клавиатуру), `/help`, `/unlink`. Список команд в меню «/» бот выставляет сам при `/start`.

Рабочее время: **08:00–19:00 по Екатеринбургу**. Напоминания (`telegram-reminders`, раз в час): вечером перед рабочим днём по графику (с прогрессом месяца), в 19:00 — «сколько чехлов?» с кнопками +500/+1000/+1500, если смена не внесена, и итоги месяца в его последний день.

Подробная настройка — в [`telegram_bot_setup.md`](telegram_bot_setup.md).

## Настройка Supabase

1. Создайте проект Supabase, включите **Authentication → Providers → Email** (для простоты — без подтверждения email).
2. В SQL Editor выполните скрипты **по порядку**:
   1. `SUPABASE_SCHEMA.sql` — таблицы `profiles / settings / shifts`, RLS, триггеры `updated_at`;
   2. `SUPABASE_ULTRA.sql` — таблица `user_app_data` (расходы, цели, шаблоны);
   3. `TELEGRAM_SUPABASE.sql` — таблицы бота и RPC `create_telegram_link_code`;
   4. `SUPABASE_ACCOUNT.sql` — RPC `delete_own_account` (удаление аккаунта из сайта и iPhone).
3. В `script.js` укажите свои `SUPABASE_URL` и publishable-ключ (`SUPABASE_PUBLISHABLE_KEY`); те же значения — в `ios/CasePlaceSalary/Config.swift`.
4. Вход через Apple и Google: **Authentication → Providers** включите Apple и Google, в **URL Configuration → Redirect URLs** добавьте `https://andrey1904-dev.github.io/my-pay/app.html` и `caseplace://auth-callback` (iPhone). Веб-авторизация возвращает пользователя на `app.html`. Подробно — в `ios/README_IOS.md`.
5. Разверните функции бота (см. `telegram_bot_setup.md`):
   ```bash
   supabase functions deploy telegram-mypay --no-verify-jwt
   supabase functions deploy telegram-reminders --no-verify-jwt
   supabase secrets set TELEGRAM_BOT_TOKEN=... TELEGRAM_WEBHOOK_SECRET=...
   ```

Если SDK Supabase не загрузился (нет сети, блокировщик), приложение работает в локальном режиме и сообщает об этом на экране «Ещё».

## Проверки перед публикацией

Нужен Node.js ≥ 22.18.

```bash
npm ci                  # зависимости UI, сборки и тестов
npm run build           # production-сборка лендинга и PWA в dist/
npm test                # проверки приложения, сайта, бота и напоминаний
npm run typecheck       # tsc --strict для Edge Functions
npm run typecheck:ui    # TypeScript лендинга
npm run check           # синтаксис + обе проверки типов + тесты
```

При обновлении версии приложения меняйте `APP_VERSION` / `CACHE_VERSION` в `script.js`, `CACHE_NAME` в `sw.js` и параметры `?v=` в `app.html` одновременно.

iOS-приложение собирается только в Xcode на Mac (см. `ios/README_IOS.md`); проверка перед публикацией — `APP_STORE.md`.

## Безопасность

- токен бота и `SUPABASE_SERVICE_ROLE_KEY` — только в Supabase Secrets, никогда в репозитории или фронтенде;
- publishable-ключ Supabase допустим на клиенте — данные защищает Row Level Security;
- вебхук принимает запросы только с правильным `X-Telegram-Bot-Api-Secret-Token`;
- функция напоминаний требует `Authorization: Bearer <service role key>`.
