# CASE.PLACE SALARY

Веб-приложение для учёта смен, упакованных чехлов и заработка сотрудника CASE.PLACE.
Версия **1.1.3 / V1.13**. Интерфейс: «Сегодня», «Календарь», «Статистика», «Ещё».

[Приложение](https://andrey1904-dev.github.io/my-pay/) · [Аудит](AUDIT.md)

## Возможности

- Учёт смен: чехлы, праздничная ставка, премия, часы и заметка.
- График 2/2 от выбранной даты; календарь, редактирование, удаление и отмена удаления.
- Статистика месяца: сумма, средняя и лучшая смена, чехлы, серия и график заработка.
- Прогноз по среднему заработку и оставшимся сменам; оценка аванса и зарплаты.
- Шаблоны смен, светлая/тёмная/системная тема.
- Локальная работа без регистрации, резервные копии JSON, экспорт CSV.
- Supabase: email/пароль, синхронизация смен и настроек, постоянная очередь изменений.
- Telegram 2.0: итог за сегодня одним числом, замена без сложения, 143 реакции, текстовые отчёты и напоминания без кнопок.

Нативное мобильное приложение, учёт личных расходов и цели удалены. PWA устанавливается из браузера.
Исторические дополнительные поля старых резервных копий сохраняются для совместимости и не отображаются.

## Как считается смена

Единый источник стандартных тарифов: `supabase/functions/_shared/pay.ts`.

```text
Обычный фикс: (1 900 + 200) × 1,15 = 2 415 ₽
Праздничный фикс: (3 800 + 200) × 1,15 = 4 600 ₽
Сделка: чехлы × 7 × 25% = чехлы × 1,75 ₽
Итого: фикс + сделка + премия
```

1 000 чехлов без премии: **4 165 ₽** обычно, **6 350 ₽** в праздник.
Часы используются для показателя дохода в час и не уменьшают фиксированную ставку.
Тарифы меняются в настройках; сохранённые смены хранят исторические суммы.
Календарь и рабочее время используют Екатеринбург (`Asia/Yekaterinburg`).

По стандартной схеме аванс 23-го — «чистый выход» за 1–15 числа (фикс / 1,15 − 200),
зарплата 8-го — заработок прошлого месяца минус этот аванс. Даты настраиваются.
Это оценка по внесённым сменам, без налогового расчёта или интеграции с бухгалтерией.

## Запуск и проверки

Node.js **≥22.18**, npm.

```bash
npm ci
npm run dev        # http://localhost:5173, исходники и обновление при изменениях
npm run check      # ESLint, TypeScript, тесты интерфейса, облака, SQL и бота
npm run build      # production в dist/, обновляет статические файлы в корне
npm run preview    # http://localhost:4173, проверка production
npm audit          # зависимости, включая инструменты разработки
```

`script.js` — генерируемый файл. Менять нужно исходники.
Сборка PWA запускается автоматически перед тестами. Service Worker в dev отключён.
Для статического хостинга публикуйте `dist/`; корневые бандлы сохранены для совместимости с GitHub Pages из ветки.

## Границы возможностей

- Оболочка PWA доступна офлайн после успешной первой загрузки и кэширования.
- Вход требует сети. Локальные правки привязаны к владельцу очереди и отправляются после восстановления связи.
- Синхронизация между устройствами использует последнее сохранение; серверного разрешения конфликтов нет.
- JSON-импорт объединяет даты смен, сохраняя записанные суммы и премии; одинаковые даты заменяются импортом.
- Браузерное напоминание работает, пока браузер выполняет код страницы. Фоновый Web Push не реализован.
- Напоминания Telegram требуют развёрнутой функции и настроенного cron. Проверка HTTP-эндпоинта не подтверждает работу расписания.

## Мобильный интерфейс V1.10

Главный URL сразу открывает «Моя смена», вход доступен в «Ещё». React-лендинг и его зависимости удалены.
Новая установка использует главный URL; прежний manifest id `./app.html` сохранён для совместимости установок.
Тёмная тема включена по умолчанию для новых данных; ранее выбранные светлая/системная темы сохраняются.
Счётчик и праздничный переключатель сохраняют смену сразу локально, затем отправляют её через прежнюю очередь.
Числовое поле сохраняется при завершении ввода (change/потере фокуса); отдельная кнопка доступна в параметрах.
Навигация использует историю браузера. Safe-area не имитирует системные элементы телефона.
SQL, storage keys и серверные функции не изменялись. Сохранённые исторические суммы отображаются без пересчёта;
изменение смены явно применяет текущие тарифы, как раньше.

Сборка создаёт очищенный `dist/` и корневой `script.js` для совместимости с legacy Pages.
Локально `npm run dev` использует Vite без SW; `npm run build && npm run preview` — production с SW.
Отчёты по этапам и ограничения: [docs/REDESIGN-STAGES.md](docs/REDESIGN-STAGES.md).

Браузерное QA (опционально, Playwright не добавлен в зависимости приложения):

```bash

# В другом терминале, с доступным playwright и установленными chromium/webkit:

# Или PLAYWRIGHT_MODULE=/absolute/path/to/playwright node scripts/browser-qa.cjs
```

Скрипт блокирует обращения к настоящему Supabase/CDN, использует синтетический backend,
сохраняет скриншоты в `screenshots/`. [Результат прогона](docs/BROWSER-QA.txt).

## Персональное приветствие V1.11

На «Сегодня» имя берётся из `extra.displayName`, затем профиля, затем метаданных Auth; без имени — «Привет ❤️».
Поле «Как к тебе обращаться?» находится в существующих настройках. Email не используется как имя.
Рабочие дни для приветствия: явная отметка в календаре → сохранённая смена (включая 0 чехлов) → график 2/2.
Выходной прерывает последовательность. Удаление записи оплаты возвращает день к графику, а не автоматически делает его выходным.
Для явного выходного выберите «План дня» в календаре. Это не удаляет оплату и не меняет формулы/прогноз по графику 2/2.
Имя и отметки сохраняются в существующем `myPayExtra` / `user_app_data.payload`, проходят через очередь и JSON-копии.
Приветствие обновляется по Екатеринбургу при смене суток и возвращении в приложение, независимо от черновика счётчика.
Подробности и проверки: [docs/PERSONAL-GREETING.md](docs/PERSONAL-GREETING.md).
