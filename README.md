# CASE.PLACE SALARY

**CASE.PLACE SALARY** — личный кабинет для сотрудников CASE.PLACE: учёт смен по графику 2/2, упаковки чехлов и заработка в одном интерфейсе.

Приложение фиксирует количество упакованных чехлов, показывает доход за смену и месяц, ведёт календарь рабочих дней, статистику, финансы и цели. Работает офлайн (данные на устройстве), а при входе в аккаунт синхронизируется через Supabase. Чехлы можно вносить прямо из Telegram.

Сайт: <https://andrey1904-dev.github.io/my-pay/>

## Возможности

- главный экран «Моя смена»: ввод чехлов, праздничная ставка, итог смены, прогресс по цели месяца;
- календарь 2/2 с внесёнными сменами, выбор дня и окно смены (чехлы, часы, премия, комментарий, шаблоны);
- статистика месяца: заработок, чехлы, средняя смена, лучшая смена, серия, график по сменам, список смен;
- финансы: свободный остаток, бюджет на день, расходы по категориям, цели накоплений, шаблоны смен;
- резервная копия и восстановление (JSON), экспорт в CSV;
- светлая, тёмная и системная темы;
- PWA: установка на экран телефона, офлайн-оболочка через Service Worker;
- аккаунт и синхронизация через Supabase (Auth + Postgres + RLS), офлайн-очередь изменений;
- Telegram-бот: ввод чехлов из чата, отчёты, отмена, напоминания.

## Дизайн v16

- Палитра CASE.PLACE: графит `#16181d` / `#17191e`, фирменный оранжевый `#ff5a1f`, тёплые светлые нейтрали `#f4f4f2` / `#ffffff`.
- Все пары «текст / фон» проверены на контраст ≥ 4.5:1 (WCAG AA); на оранжевых заливках используется тёмный текст.
- Минимальный размер текста — 11 px, основной — 15 px, единая сетка отступов и радиусов.
- Тёмная тема — отдельный набор токенов (`body.dark`), а не инверсия; инверсные элементы (внесённые дни, тёмные кнопки) автоматически меняют полярность.
- Свои диалоги подтверждения и ввода суммы вместо системных `confirm()` / `prompt()`.

## Модель оплаты

- Обычная смена: 1 900 ₽ дневной тариф + 727,84 ₽ районный коэффициент = **2 627,84 ₽**.
- Сдельная часть: 44 284,28 ₽ / 26 093 чехла ≈ **1,69 ₽ за чехол** (настраивается процент сделки).
- Праздничная смена: фиксированная часть **4 050 ₽** (редактируется в настройках).
- `итог = ставка + чехлы × цена × процент / 100 (+ премия)`.

Все параметры меняются в «Ещё → Настройки расчёта» и синхронизируются с таблицей `settings`.

## Telegram-бот

Бот принимает число чехлов и обновляет смену за сегодня:

- `350`, `350 + 500`, `чехлы 350`, `упаковал 1200 чехлов` — задать значение (если смена уже внесена, бот спросит: добавить или заменить);
- `+500` — добавить к текущему значению;
- кнопки `+100 / +500 / +1000`, `Сегодня / Месяц / Прогноз`, `Отменить / Помощь`;
- `/today`, `/month`, `/forecast`, `/last`, `/undo`, `/holiday`, `/notify_on`, `/notify_off`, `/menu`, `/help`, `/unlink`.

После добавления бот показывает количество чехлов, мотивационное сообщение, заработок за смену (ставка + сделка) и время до конца рабочего дня. Рабочее время: **08:00–19:00 по Екатеринбургу**.

Напоминания (`/notify_on`): вечером перед рабочим днём по графику и в 19:00, если смена за рабочий день ещё не внесена. Их рассылает отдельная функция `telegram-reminders`, запускаемая по расписанию.

Подробная настройка — в [`telegram_bot_setup.md`](telegram_bot_setup.md).

## Запуск сайта

Проект не требует сборки — это статические файлы.

1. Загрузите файлы в репозиторий GitHub.
2. Откройте **Settings → Pages**, выберите ветку `main` и папку `/ (root)`.
3. После публикации откройте сайт; для установки на телефон — «Ещё → Добавить на экран телефона».

Локально: `npm start` (или `python3 -m http.server 8080`) и открыть <http://localhost:8080/>.

## Настройка Supabase

1. Создайте проект Supabase, включите **Authentication → Providers → Email** (для простоты — без подтверждения email).
2. В SQL Editor выполните скрипты **по порядку**:
   1. `SUPABASE_SCHEMA.sql` — таблицы `profiles / settings / shifts`, RLS, триггеры `updated_at`;
   2. `SUPABASE_ULTRA.sql` — таблица `user_app_data` (расходы, цели, шаблоны);
   3. `TELEGRAM_SUPABASE.sql` — таблицы бота и RPC `create_telegram_link_code`.
3. В `script.js` укажите свои `SUPABASE_URL` и publishable-ключ (`SUPABASE_PUBLISHABLE_KEY`).
4. Разверните функции бота (см. `telegram_bot_setup.md`):
   ```bash
   supabase functions deploy telegram-mypay --no-verify-jwt
   supabase functions deploy telegram-reminders --no-verify-jwt
   supabase secrets set TELEGRAM_BOT_TOKEN=... TELEGRAM_WEBHOOK_SECRET=...
   ```

Если SDK Supabase не загрузился (нет сети, блокировщик), приложение работает в локальном режиме и сообщает об этом на экране «Ещё».

## Проверки перед публикацией

Нужен Node.js ≥ 22.18 (TypeScript функций исполняется без сборки).

```bash
npm install            # jsdom + typescript (только для тестов)
npm test               # 72 проверки: фронтенд (jsdom) + бот и напоминания
npm run typecheck      # tsc --strict для Edge Functions
npm run check          # синтаксис script.js/sw.js + typecheck + тесты
```

При обновлении версии меняйте `APP_VERSION` / `CACHE_VERSION` в `script.js`, `CACHE_NAME` в `sw.js` и параметры `?v=` в `index.html` одновременно.

## Безопасность

- токен бота и `SUPABASE_SERVICE_ROLE_KEY` — только в Supabase Secrets, никогда в репозитории или фронтенде;
- publishable-ключ Supabase допустим на клиенте — данные защищает Row Level Security;
- вебхук принимает запросы только с правильным `X-Telegram-Bot-Api-Secret-Token`;
- функция напоминаний требует `Authorization: Bearer <service role key>`.
