# Аудит CASE.PLACE SALARY (My Pay) — v12

## Найдено и исправлено

### Критично
1. **JavaScript не запускался** — первая строка `script.js` начиналась с `/ v11...`, что является синтаксической ошибкой.
   - Исправлено на нормальный комментарий.
   - Проверено `node --check`.

2. **Вход после авторизации мог падать** — `updateProfileUI()` обращался к `#profileName` и `#profileAvatar`, которых не было в HTML.
   - Добавлены оба элемента.
   - Профиль теперь загружается из Supabase.

3. **Смешивание данных разных аккаунтов на одном устройстве**.
   - При авторизованной загрузке облако является источником истины.
   - Пустой облачный список смен теперь очищает старые локальные смены.
   - При выходе состояние очищается.

### Потеря/рассинхронизация данных
4. **Удаление смены могло удалить её локально даже при ошибке Supabase.**
   - Добавлен rollback.

5. **«Очистить месяц» игнорировал ошибки отдельных удалений.**
   - Теперь удаляются локально только успешно удалённые из облака записи.
   - Пользователь получает сообщение о количестве неудачных удалений.

6. **Импорт JSON принимал строки/мусор вместо чисел**, что могло ломать арифметику статистики.
   - Импорт нормализует даты, количество чехлов и пересчитывает зарплату по текущим настройкам.

### PWA / кеш
7. **Service Worker снимался при каждом запуске приложения.**
   - Убран агрессивный `unregister()`.
   - Старые `my-pay-v*` кеши удаляются, активный worker сохраняется.
   - Версия поднята до v12.

### UX / доступность
8. Модальные окна теперь закрываются по `Esc` и клику по затемнённой области.
9. Кнопки переключения месяца получили `aria-label`.

## Архитектурные замечания

- Supabase publishable key допустим на клиенте; RLS остаётся обязательной защитой данных.
- Реальные фоновые Web Push всё ещё требуют VAPID-ключей, сохранения PushSubscription и настроенного cron/Edge Function. Текущий локальный fallback уведомляет только пока приложение может выполнить JS.
- Для production желательно подключить автоматический `updated_at` trigger для таблиц Supabase и мониторинг ошибок Edge Function.

# Аудит My Pay — v15 (2026-09-28)

## Критично

1. **Приложение удаляло собственный кеш service worker'а.**
   `script.js` чистил все кеши `my-pay-v*`, кроме `my-pay-v14`, а `sw.js` работал с `my-pay-v13`.
   Итог: precached-оболочка стиралась при каждом запуске, офлайн-режим не работал.
   → Введена единая константа `CACHE_VERSION` (v15) в обоих файлах.

2. **Кнопка «Сохранить смену» на главной писала не в ту дату.**
   `saveHomeShift()` использовала `state.selectedDate`, который меняется при выборе дня в календаре.
   После просмотра другого дня домашнее сохранение уходило в старую дату.
   → Главный экран всегда сохраняет сегодняшний день.

3. **Облако затирало пользовательские настройки при каждом входе.**
   В `cloudLoad()` условие легаси-миграции срабатывало не только на старую тройку 2150/7/20,
   но и на любую цену чехла ≈1.69 или ≈2 — из-за этого `base_pay` и `percent`
   принудительно сбрасывались на 2627.84 / 100.
   → Миграция теперь только по точной легаси-тройке.

4. **Дублирование глобальных обработчиков при каждой навигации.**
   Внутри `nav-item.onclick` была скопирована регистрация `click` по фону модалок и `keydown` по Esc.
   Каждый переход по таб-бару добавлял новую пару слушателей (утечка + многократные вызовы).
   → Дубли удалены, слушатели регистрируются один раз.

5. **Пустой экран вместо приложения, если не загрузился Supabase SDK.**
   `window.supabase.createClient(...)` вызывался без проверки: при блокировке CDN или офлайне
   падал весь `script.js`, и пользователь видел пустоту без входа в аккаунт.
   → Добавлен локальный режим: баннер «Облако недоступно», все данные хранятся на устройстве.

## Потеря данных

6. **Расходы, цели и шаблоны не синхронизировались офлайн.**
   `cloudSaveExtra()` при отсутствии сети просто возвращал `false` — правки оставались только
   на устройстве без шанса догрузиться.
   → Добавлен тип `saveExtra` в офлайн-очередь и его обработка в `flushCloudQueue()`.

7. **Статистика не обновлялась после редактирования смены в модалке.**
   `saveModal()` / `deleteModal()` / `deleteHistoryShift()` не перерисовывали инсайты
   и домашний дашборд — на экране оставались старые суммы.
   → Добавлены `renderInsights()` и `updateHome()`.

8. **Импорт резервной копии мог ложно сообщать об ошибке.**
   Проверка сравнивала общее число смен в облаке с числом смен в файле: если в облаке были
   дополнительные записи, показывалось «облачная проверка не прошла».
   → Проверяются только импортированные даты.

## Прочее

10. Пароль в форме регистрации получал `autocomplete="current-password"` — исправлено на `new-password`.
11. Двойная одновременная синхронизация после входа (`authAction` + `onAuthStateChange`) —
    добавлен guard `afterLoginInFlight`.
12. Версия SDK Supabase была плавающей `@2` — зафиксирована `2.117.2` (проверенная сборка).
13. `theme_color` манифеста (`#111522`) не совпадал с `theme-color` страницы (`#ff5a1f`) — унифицировано.
14. Добавлено обновление данных при возврате на вкладку (`visibilitychange`) и при появлении сети.

## Ошибки в приложении

4. **Праздничная ставка была захардкожена** (4 050) в расчёте и подписи, хотя в базе есть `holiday_pay`.
   → Поле «Праздничная ставка» в настройках, значение участвует в расчёте, синхронизации и бэкапе.
5. **Данные из облака перетирали поле ввода на главной** во время набора (фоновое обновление раз в 30 с).
   → Флаг `homeDirty`; фоновая синхронизация пропускается, пока поле правится, открыта модалка или вкладка скрыта.
6. **Прогноз месяца считался по календарным дням**, а не по графику 2/2, и показывал число даже без смен.
   → Прогноз = заработано + средняя смена × оставшиеся рабочие дни по графику (включая сегодняшний, если не внесён); без смен — «—».
7. **Системные `confirm()` / `prompt()`** в PWA выглядели чужеродно, а на iOS в standalone-режиме иногда не показывались.
   → Свои диалоги `confirmAction()` / `promptNumber()` (промисы), используются для удаления, очистки месяца, выхода, пополнения цели.
8. **`scheduleStart` из облака мог прийти не строкой `YYYY-MM-DD`** (timestamp) и ломал расчёт графика.
   → Проверка `isDateKey`, иначе — сегодняшняя дата.
9. **Статус Telegram-привязки не показывался** — приложение не читало `telegram_links`.
   → `loadTelegramStatus()`: имя/username и дата привязки на экране «Ещё» и в окне бота.
10. **Слушатели фонового обновления регистрировались повторно** при каждом входе. → Guard `cloudListenersBound`.
11. **`theme-color` не менялся при смене темы** — статус-бар оставался светлым в тёмной теме. → Синхронизация всех `meta[name=theme-color]`.
12. `num()` считал `null`/пустую строку нулём, из-за чего пустое поле цели превращало цель в 0. → Пустые значения = дефолт; принимаются запятые как разделитель.
13. Кнопка «Выйти из аккаунта» показывалась без входа. → Скрывается, пока нет пользователя.
14. Форматирование денег: `30 014,4 ₽` → всегда две цифры после запятой, если сумма не целая.
15. `sw.js` и `script.js`: единая версия кеша `my-pay-v16`, в оболочку добавлены `script.js?v=16` и `style.css?v=16`.
