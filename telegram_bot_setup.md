# CASE.PLACE SALARY — основная клавиатура Telegram

Бот развёрнут в Supabase Edge Functions, PWA — отдельно на GitHub Pages.
Общие аккаунты, смены и данные находятся в Supabase.

## Основная клавиатура

Единственный ReplyKeyboardMarkup, строго 2×3:

```text
📦 Сегодня | 📊 Месяц | 🔮 Прогноз
📅 Календарь | 💸 Расходы | ⚙️ Ещё
```

`resize_keyboard=true`, `one_time_keyboard=false`, `is_persistent=true`.
Параметры поддерживаются официальным Telegram Bot API; библиотека-обёртка отправляет
обычный JSON без сторонних зависимостей. Клиент определяет внешний вид и сохранение
состояния между перезапусками. При каждом обычном ответе та же клавиатура передаётся
в одном сообщении, включая /start, привязку, отчёты, сохранение и напоминания.
ReplyKeyboardRemove не используется, кнопок +100/+500/+1000 нет.

## Ввод смены и шутки

Целое число 0–20 000 (также `1 250`) — итог за сегодняшний день Asia/Yekaterinburg.
Следующее число заменяет прежнее. Повтор того же числа не обновляет строку смены.
Пустая смена создаётся даже в выходной. Ответ: статус, фактический заработок, шутка;
отдельной строки количества и inline-действий после сохранения нет.

`_shared/telegram-jokes.ts` не изменён: 141 уникальный порог 500–4000 через 25 и
две специальные реакции. Выбор детерминированный, округление вниз.
Ставки, премии, праздничный признак, история и защита update_id/CAS сохранены.

## Разделы

Сегодня — дата/график/смена/заработок. Месяц — внесённые смены, сумма, средняя,
лучшая смена и прогноз. Прогноз различает уже заработанное и ожидаемый итог.
Календарь использует существующую сетку и расчёты. Его навигация по месяцам восстановлена
из истории 8f339e0/ca63be4 и адаптирована к основной клавиатуре:

- `/calendar` — текущий месяц;
- `/calendar 2026-10` или короткая нажимаемая команда `/cal_2026_10` — выбранный;
- команды предыдущего/текущего/следующего месяца находятся под сеткой;
- старые inline callback `cal:YYYY-MM` и `v:calendar` также снова работают, редактируя
  старую календарную карточку и её inline-навигацию.

Telegram допускает один вид reply_markup на сообщение и не позволяет редактировать
сообщения с ReplyKeyboardMarkup как inline-карточки. Поэтому новые календарные ответы
содержат основную клавиатуру и короткие команды навигации, без второго сообщения.
Прежние быстрые добавления, undo/holiday и изменение настроек через старые callback
не восстановлены: они не должны обходить защищённый сценарий дневного итога.

Ещё — ставки, график, состояние напоминаний, /notify_on, /notify_off, /help, /last,
/unlink и приложение. Второй постоянной клавиатуры нет.

## Расходы

Функционал расходов был удалён ещё в 5586704/c3d8e1b, до обновления Telegram 2.0.
Восстановлены прежние типы/категории/подбор счёта и месячная сводка из 8f339e0,
без возврата старых обработчиков выработки. Хранилище то же: user_app_data.payload.
Открытие раздела ничего не создаёт, не удаляет и не пересчитывает в финансовых данных.

- 💸 Расходы, `/spent`, `/expenses`, `/finance` — месяц, категории, лимиты и последние операции с ID;
- `/expense 350 обед` — явное добавление расхода;
- `/income 1000 подарок` — явное добавление дохода;
- `/delete_expense ID` — удаление расхода/дохода только в собственном аккаунте;
- обычное `350` всегда выработка; `350 обед`, `-1200`, дроби и выражения не становятся
  операциями без явной финансовой команды.

Сумма финансовой команды: положительное число до 1 млрд с максимум двумя десятичными
знаками, обязательно описание. Сохранение использует условный UPDATE по updated_at
или уникальный INSERT, сохраняет прочие поля JSON, категории, счета и историю.
Идентификатор операции детерминирован по update_id. Маркер telegramFinanceUpdates
сохраняется в том же атомарном JSON, включая после удаления операции: повтор update
не может создать дубль или воскресить удалённый расход. Конфликт не перезаписывает данные.

PWA V1.14 при сохранении своих настроек/шаблонов читает свежий JSON, сохраняет актуальные
transactions/categories/accounts/telegramFinanceUpdates и выполняет CAS с ограниченными
повторами. Старая офлайн-копия метаданных не затирает финансовый журнал Telegram.
Интерфейс расходов в PWA не воссоздавался: он был убран прежним упрощением проекта;
данные остаются общими и сохраняются при синхронизации и экспорте.

## Проверки и ограничения

Тесты проверяют 2×3/подписи/порядок/флаги, все разделы, восстановление клавиатуры,
один ответ, маршрутизацию, календарную навигацию, сохранение/замену/повтор, расчёт,
все пороги шуток, защиту расходов/повторов/конфликтов/чужих данных и синхронизацию.

Временная service-only функция telegram-smoke проверяет отдельный auth-аккаунт,
боевой webhook, Supabase/RLS, клавиатуру, разделы, расходы и календарь. Исходящие
Telegram API перехватываются; реальный webhook вызывается только с невозможным ID чата.
После проверки функция и тестовые данные, включая события, удаляются.
Визуальное поведение клиента и сохранение после его перезапуска требуют настоящего
тестового чата; API payload не доказывает визуальное отображение на конкретном устройстве.

В production ранее отсутствовала cron.job; автоматический запуск напоминаний не доказан.
Существующая логика, service-key авторизация и дедупликация сохранены; новый cron не создаётся.
Пользователям старой открытой PWA нужно обновить страницу до V1.14 для защиты финансовых
данных при сохранении настроек. Сохранение финансовой команды при конкурентном изменении
может попросить повторить её новым сообщением; незаметного перезаписывания нет.

## Откат

Предыдущие функции выгружены до публикации. Повторно задеплоить их сохранённые исходники;
PWA вернуть через revert PR к предыдущему main и дождаться Pages. Данные смен/финансов,
служебные маркеры и прежний аддитивный SQL не удалять. Новые migration не требуются.
